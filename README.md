# Property Graph, Semantic Layer, or Plain SQL? — Replication Package

This package accompanies the ICDE EAB paper *"Property Graph, Semantic Layer, or Plain SQL? An Experimental Study of LLM Question Answering over Multi-Level Product Composition Data"*.

It contains everything needed to rebuild the three benchmark datasets, regenerate every question and gold answer, re-run every substrate with any OpenAI-compatible LLM endpoint, and regenerate all tables, figures and numbers in the paper from the released raw results.

## Reproducing

Use Python 3.9+ and `pip install -r requirements.txt` (`duckdb==1.4.5`, `kuzu==0.11.3`, matplotlib for the figures). The second graph engine is Neo4j 5.26 Community with JDK 21. All model calls were made between 2026-11-03 and 2026-11-10 through OpenAI-compatible endpoints (`deepseek-flash`, `deepseek-v4-pro`, `kimi-k2.6` from the vendors; `gpt-6-sol`, `claude-opus-5-5`, `Qwen3.8-27B`, `glm-5.3` through a gateway; `kimi-k3-1-pro-261024` through Volcengine Ark; `glm-4.5-air` in the pilot).

1. **Build the source snapshots.** Run `python code/make_sources.py --raw raw --out data`. It writes `data/{aw,lego,xb}_src.duckdb`, and the result is table-for-table identical to the snapshots used in the paper.
   - XB is produced by a seeded generator.
   - AdventureWorks is built from the CSV exports in `raw/aw/`, which are taken from [microsoft/sql-server-samples](https://github.com/microsoft/sql-server-samples) under the MIT license.
   - LEGO needs the Rebrickable catalog downloads (`*.csv.gz` from rebrickable.com/downloads) in `raw/rebrickable/`. They are not redistributed here. Data sourced from Rebrickable (https://rebrickable.com), whose terms permit any use with attribution; please respect them, including the prohibition on using Rebrickable content to train AI models.
2. **Build the substrates.**
   - XB: `python code/build_substrates.py`.
   - AdventureWorks and LEGO: `python code/datasets/aw/build.py` and `python code/datasets/lego/build.py`.
3. **Regenerate and check the questions.** Run `gen_questions.py` and `check_gold.py` for each dataset. The generators are seeded, so reruns are byte-identical. The gold answers agree with the metric-layer oracle on every covered question.
4. **Run the substrates.**
   ```
   N1_DATASET=aw python code/run_pilot.py --models <m> --substrates sql,sql_u,cypher,cypher_u,semantic,classify --out main_aw.jsonl
   ```
   Set `N1_KEYS_ROOT` to a directory that contains `.secrets/llm_keys.json` with `{provider: {api_key, base_url}}`. `run_agent.py` takes the same arguments. The other substrates are selected with `--substrates`:
   - `cypher_h`: Graph-T with the multi-type pattern note (documentation ablation).
   - `semantic_abs`: Metric with an optional `UNSUPPORTED` answer.
   - `neo_t` and `neo_u`: the two graphs on Neo4j 5.
   - `classify`: Metric-R.
   
   For Neo4j, `code/neo4j_build.py <kuzu_db> <ds>_<t|u> <port_offset>` copies a Kùzu graph into a dedicated local Neo4j instance with identical labels, types and properties. `code/run_neo4j_all.sh` runs the replication; it expects a JDK 21 and a Neo4j 5.26 Community tarball unpacked under `.tools/`.
   - SQL-X and Graph-X: `python code/build_closure.py --ds <xb|aw|lego>` after step 2, then `python code/check_closure.py`.
   - MetricFlow: create a separate environment (`python -m venv .tools/mf_venv; .tools/mf_venv/bin/pip install dbt-metricflow==0.11.0 dbt-duckdb==1.10.0`) and run `.tools/mf_venv/bin/python code/metricflow/build.py`, then `python code/check_mf.py`.
   - `code/run_v3*.sh` are the drivers of the review round (dialect notes, Graph-X usage note, second repetition of SQL-X/Graph-X, thinking contrast, fresh question set, truncation re-runs); `code/run_v4*.sh` those of the final round (thinking for all main models, fresh set on every substrate, few-shot, agent variants, third labeler).
   - `code/run_v2*.sh` are the drivers of the final round (uniform Cypher note, further models, second repetition, SQL-X/Graph-X, MetricFlow, paraphrases). Models served through an OpenAI-compatible gateway (`gpt-6-sol`, `claude-opus-5.5`, `qwen3.8-27b`) read `LLMHUB_BASE_URL` and `LLMHUB_API_KEY` from the environment.
5. **Regenerate the paper's numbers and figures.** Run `python code/analyze_main.py`, which writes `paper/numbers.tex` and the tables, and `python code/analyze_v4.py`, which writes `paper/numbers_v4.tex`, then `python code/make_figs_main.py`. `python code/analyze_erp.py` writes `paper/numbers_erp.tex` for the enterprise case.

## Notes

- Every Kùzu query runs in its own process (`kuzu_exec.py`), because a generated query can crash the engine.
- DuckDB spill space is capped at 300 MB per connection.
- The enterprise case study uses de-identified proprietary data. Its schema, questions, queries and answers are not released; the package contains instead the per-execution outcome records from which every enterprise number in the paper is recomputed. All benchmark conclusions rest on the three public datasets.
