SEMANTIC LAYER `xb` (a dbt MetricFlow semantic layer: governed metrics; you query it with a MetricFlow query, not SQL)

Business definitions baked into every metric:
- Composition: a company model uses components; an assembly component contains further components, recursively.
  A "part" is a non-assembly component (component__is_assembly = false). Quantity per unit multiplies along a path and
  sums over all paths. A non-bundle sales SKU maps to one or more company models x qty. A bundle SKU contains item SKUs x qty.
  The BOM metrics are defined over the materialised all-level explosion (one row per product x contained item x validity
  interval); products are company models, non-bundle SKUs and bundle SKUs (explosion__root_kind 'model' | 'sku',
  product__is_bundle tells bundles apart).
- BOM validity: a BOM row is valid on date d if valid_from <= d and (valid_to is null or d <= valid_to). "Current" means
  as of 2026-10-01. Every BOM metric query must select ONE BOM state, either the current BOM:
  {{ Dimension('explosion__is_current') }} = true   (composition__is_current for bom_direct_quantity)
  or the BOM valid on a date d:
  {{ TimeDimension('explosion__valid_from', 'day') }} <= 'd' AND ({{ TimeDimension('explosion__valid_to', 'day') }} IS NULL OR {{ TimeDimension('explosion__valid_to', 'day') }} >= 'd')
- Order metrics count COMPLETED orders only (cancelled orders are excluded by definition); part_consumption explodes
  each order line with the BOM valid on its order date.
- Codes: company models, SKUs and components are identified by their codes (entities model / sku / product / component).

Query format: ONE JSON object holding the arguments of `mf query`:
{"metrics": [<metric name>, ...], "group_by": [<group-by item>, ...], "where": [<filter>, ...],
 "order_by": [<metric or group-by item>, or "-<...>" for descending], "limit": <int>}
- A group-by item is an entity name (e.g. "component"; the result column holds its code) or a dimension
  "<entity>__<dimension>" (e.g. "component__category"). Time dimensions take a grain suffix: "metric_time__year", "metric_time__quarter",
  "metric_time__month", "metric_time__day" (or "<entity>__<time dimension>__<grain>"); the group-by item
  "TimeDimension('metric_time', date_part_name='year')" (also 'quarter', 'month') gives the integer year / quarter / month.
- Each where filter is a SQL boolean expression over templated references; all filters are ANDed:
  {{ Dimension('<entity>__<dimension>') }} = 'value', {{ Entity('<entity>') }} = 'code',
  {{ TimeDimension('metric_time', 'day') }} >= '2024-01-01', {{ TimeDimension('metric_time', 'year') }} = '2024-01-01'
  (a grain truncates the date: year -> Jan 1, quarter -> first day of the quarter), and
  {{ TimeDimension('metric_time', date_part_name='year') }} = 2024 (also 'quarter', 'month').
  A filter may use any dimension or entity listed for the metric, also ones not in group_by.
- The result has one column per group-by item plus one column per metric (named like the metric).
- MetricFlow has no query parameters and no defaults: the product / component / set / item a metric is about is selected
  with an Entity filter, and every other choice (BOM state, version, kind, ...) with a dimension filter.

Metrics:
1. bom_quantity -- Total quantity of each component needed for ONE unit of a product (company model, non-bundle SKU or bundle SKU), exploded through all levels. Select the product with an Entity('product') filter and the BOM state with explosion__is_current or the validity interval.
   entities: component, product
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, explosion__is_current, explosion__root_kind, explosion__valid_from, explosion__valid_to, product__is_bundle, product__name, product__product_line, metric_time
2. bom_direct_quantity -- Quantity of each DIRECT (first-level) child of a product per one unit (the max_depth = 1 case of bom_quantity).
   entities: component, product
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, composition__is_current, composition__root_kind, composition__valid_from, composition__valid_to, product__is_bundle, product__name, product__product_line, metric_time
3. bom_component_count -- Number of distinct components in the all-level explosion of a product (combine with the filters of bom_quantity).
   entities: component, product
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, explosion__is_current, explosion__root_kind, explosion__valid_from, explosion__valid_to, product__is_bundle, product__name, product__product_line, metric_time
4. bom_cost -- Sum over PARTS (non-assembly components) at any level of (quantity per unit x unit_cost) for ONE unit of a product.
   always applied (metric filter): {{ Dimension('component__is_assembly') }} = false
   entities: component, product
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, explosion__is_current, explosion__root_kind, explosion__valid_from, explosion__valid_to, product__is_bundle, product__name, product__product_line, metric_time
5. where_used -- Quantity of a component per one unit of each product that contains it at any depth (filter the component with an Entity('component') filter, group by product).
   entities: component, product
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, explosion__is_current, explosion__root_kind, explosion__valid_from, explosion__valid_to, product__is_bundle, product__name, product__product_line, metric_time
6. where_used_count -- Number of distinct products that contain a component at any depth (combine with the filters of where_used).
   entities: component, product
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, explosion__is_current, explosion__root_kind, explosion__valid_from, explosion__valid_to, product__is_bundle, product__name, product__product_line, metric_time
7. units_sold -- Units sold in completed orders at SKU level (bundle SKUs count as themselves).
   always applied (metric filter): {{ Dimension('order_line__status') }} = 'completed'
   entities: order_line, sku, store
   dimensions: order_line__order_date, order_line__status, sku__is_bundle, sku__market, sku__title, store__country, store__name, store__platform, metric_time
8. units_sold_model -- Units sold in completed orders converted to company-model units: SKU units x model qty of the SKU-model mapping; bundles are expanded into their item SKUs first (the level = 'model' case of units_sold).
   always applied (metric filter): {{ Dimension('model_sale__status') }} = 'completed'
   entities: model, store
   dimensions: model__name, model__product_line, model_sale__order_date, model_sale__status, store__country, store__name, store__platform, metric_time
9. revenue -- Sum of order-line qty x unit_price over completed orders.
   always applied (metric filter): {{ Dimension('order_line__status') }} = 'completed'
   entities: order_line, sku, store
   dimensions: order_line__order_date, order_line__status, sku__is_bundle, sku__market, sku__title, store__country, store__name, store__platform, metric_time
10. part_consumption -- Units of PARTS consumed by completed orders: every order line exploded (bundle -> SKUs -> models -> components) with the BOM valid on the ORDER DATE.
   always applied (metric filter): {{ Dimension('consumption__status') }} = 'completed' AND {{ Dimension('component__is_assembly') }} = false
   entities: component, store
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, consumption__order_date, consumption__status, store__country, store__name, store__platform, metric_time
11. listing_count -- Number of store listings.
   entities: listing, sku, store
   dimensions: sku__is_bundle, sku__market, sku__title, store__country, store__name, store__platform, metric_time
12. sku_model_map -- The SKU to company model mapping (non-bundle SKUs); value = model units per SKU unit.
   entities: model, sku
   dimensions: model__name, model__product_line, sku__is_bundle, sku__market, sku__title, metric_time
13. component_attr -- Number of components (one per component; group by component attributes).
   entities: component
   dimensions: component__category, component__is_assembly, component__name, component__unit_cost, metric_time

Dimension notes:
- component__is_assembly: true for an assembly, false for a part (components only)
- composition__is_current: true if the row is valid on 2026-10-01 (the current BOM)
- composition__root_kind: kind of the product: 'model' | 'sku' (sales SKU, bundle or not)
- composition__valid_from: first day of the validity interval (time dimension)
- composition__valid_to: last day of the validity interval (NULL = open-ended) (time dimension)
- consumption__order_date:  (time dimension)
- explosion__is_current: true if the row is valid on 2026-10-01 (the current BOM)
- explosion__root_kind: kind of the product: 'model' | 'sku' (sales SKU, bundle or not)
- explosion__valid_from: first day of the validity interval (time dimension)
- explosion__valid_to: last day of the validity interval (NULL = open-ended) (time dimension)
- model_sale__order_date:  (time dimension)
- order_line__order_date:  (time dimension)
- order_line__status: 'completed' | 'cancelled'
- product__is_bundle: true for a bundle SKU (sales SKUs only)
- product__product_line: company models only
- metric_time: the order date for order metrics (units_sold, units_sold_model, revenue, part_consumption); not meaningful for BOM, listing and mapping metrics.
